## What it does

Agents commit to the first idea that works. This skill makes the agent stop at a real decision, name two to four different approaches, and score them from 0 to 10 on dimensions that come from the task itself. Then it picks one, or builds a hybrid from the strongest parts, and keeps going.

I use it all the time, mostly inline: "use consider-contrast for the storage choice, then continue."

## The rule that makes it work

No stock columns. Cost, speed, risk, complexity, and ease are banned unless the task makes one of them decision-critical, and then it gets renamed to the actual effect. For a database migration that means lock duration and rollback fidelity, not "risk." Each dimension has to be relevant, specific, able to separate the options, and distinct from the others.

That one rule is the difference between a comparison that changes the decision and a balanced scorecard that just looks thorough.

## It's working if

- Every column name would look strange in an unrelated decision.
- The agent continues the task after the table instead of stopping.
